# Boston Watch — מעקב חינמי אחר בוסטון טרייר לאימוץ

פרויקט התחלתי פתוח: סריקה מתוזמנת ב-GitHub Actions, היסטוריית מודעות ב-JSON, דשבורד GitHub Pages, והתראת Gmail על מודעה חדשה.

**סטטוס:** אב-טיפוס שנבדק מקומית ביחידות, אבל **טרם הורץ מול האתרים החיים מתוך GitHub**. כרגע שתי כתובות Findog ממוקדות מוגדרות. פייסבוק, יד2, יד4 ומאגרי עמותות עדיין **לא** מכוסים בפועל. לא להציג את המערכת ככיסוי מלא.

## מה מקבלים בחינם?
- GitHub Actions: ניסיון לסריקה בכל שעה, בדקה 17; GitHub עשוי לעכב או לדלג על ריצות. בריפו ציבורי, משימות מתוזמנות עשויות להיות מושבתות אחרי 60 ימי חוסר פעילות, אף שהבוט עצמו מבצע commits כשהוא רץ.
- GitHub Pages: אתר ציבורי וסטטי עם תוצאות והיסטוריית בדיקות.
- Gmail SMTP: התראות ללא שירות צד שלישי בתשלום, בשימוש בסיסמת אפליקציה ייעודית של Google (כשזמינה בחשבון).

## הקמה — כ-10 פעולות חד-פעמיות
1. פתחו חשבון ב-[GitHub](https://github.com/) אם אין לכם.
2. צרו repository חדש בשם `boston-watch` עם **Public**. פרויקט ציבורי פירושו שהמודעות והיסטוריית הסריקות פומביות. לעולם לא להעלות סיסמאות או כתובות מייל לתוך הקוד.
3. העלו את **תכולת התיקייה** הזאת ל-root של ה-repository. חשוב להעלות גם את התיקייה הנסתרת `.github/workflows` (דרך Git או העלאת קבצים התומכת בכך).
4. עברו אל **Settings → Pages → Build and deployment → Deploy from a branch**. בחרו `main`, תיקיית `/docs`, ושמרו.
5. עברו אל **Settings → Secrets and variables → Actions**, ואז **New repository secret**. הוסיפו `SMTP_USER` = כתובת Gmail ממנה יישלחו מיילים.
6. הוסיפו `SMTP_PASSWORD` = **Google App Password**, לא סיסמת Gmail הרגילה. לעתים נדרש להפעיל אימות דו-שלבי; ייתכן שבחשבונות ארגוניים אין גישה לאפשרות.
7. הוסיפו `ALERT_EMAIL` = כתובת המייל אליה לשלוח הודעות (יכולה להיות אותה כתובת).
8. פתחו לשונית **Actions → Boston Terrier hourly watch → Run workflow** והריצו פעם אחת.
9. פתחו **Settings → Pages** כדי לראות את קישור האתר שלכם. בדרך כלל `https://USERNAME.github.io/boston-watch/` (תחליפו את USERNAME).
10. בדקו בלשונית Actions האם שני המקורות הוחזרו בהצלחה. אם אתר משנה את מבנה המודעות, ייתכן שיידרש לעדכן את הסקרייפר.

## התנהגות ההתראות
- בריצה הראשונה: נוצרת נקודת בסיס ללא התרעה על מודעות ישנות, כדי להימנע מספאם.
- בריצות הבאות: מייל נשלח רק על URL חדש שלא נראה קודם.
- אם אין secrets מוגדרים: המעקב והדשבורד ממשיכים לפעול, אבל לא נשלח מייל.
- אם משלוח מייל נכשל: מופיעה שגיאה בלוג, ויש לבחון אותה. **שימו לב:** הפרויקט הבסיסי הזה עלול שלא לנסות לשלוח שוב מודעה שנשמרה כבר בהיסטוריה. לשימוש אמין יותר כדאי להוסיף תור הודעות עם retries.

## הוספת מקורות חדשים
`config.json` מכיל מקורות. ניתן להוסיף RSS ציבורי בפורמט:

```json
{"name":"Custom adoption RSS","type":"rss","url":"https://example.org/adoptions.rss"}
```

כדאי להימנע מהוספת כתובות שאינן מזינות RSS תקין. פייסבוק וקבוצות סגורות אינן נתמכות. אין לעקוף חסימות, התחברות או תנאי שימוש. סורק Findog מחפש קישורי מודעות בתבניות ידועות בלבד ומסנן תוצאות מומלצות; אם הנתיב של מודעות בפועל שונה, לא יוחזרו מודעות עד לתיקון הלוגיקה.

## בדיקה מקומית
```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python monitor.py
python -m http.server 8000 --directory docs
```
בדפדפן: `http://localhost:8000/`.

**הערה:** אין כיום זיהוי AI של תמונות בפרויקט זה, רק סינון טקסט. אפשר להוסיף זאת בשלב נוסף, אבל לא כדאי להבטיח בחינם זיהוי תמונות אמין מאתרים שאינם נגישים באופן אוטומטי.

## זיהוי מתמונות — גרסת ניסוי אופציונלית (v0.2)
כעת נוסף `vision.py` המאפשר **למצוא מועמדים חזותיים גם כשהמודעה לא מכילה את המילים בוסטון טרייר**. הוא נעזר ברשת MobileNetV3-Small שאומנה מראש על ImageNet-1K, עם מחלקת `Boston bull`, ומריץ סיווג מקומי ללא API בתשלום. אין צורך ליצור מאגר תמונות משלנו. זוהי **התאמה חזותית לבדיקה ידנית**, לא אימות גזע או הסתברות כי הכלב גזעי. בולדוג צרפתי, פאג וכלבים מעורבים עלולים להיות דומים; גם בוסטון טרייר אמיתי עשוי לא להיות מזוהה.

כדי להפעיל זאת, יש להוסיף *מקור RSS ציבורי כללי שמציג תמונה בכל פריט* בתוך `config.json`, למשל:

```json
{"name":"Public adoption feed","type":"rss_visual","url":"https://YOUR-ACTUAL-ADOPTION-FEED.example/rss"}
```

**כתובת הדוגמה אינה מקור אמיתי ואין להשתמש בה כפי שהיא.** כרגע אין מקור כזה מוגדר ולכן הסריקה הוויזואלית אינה מופעלת עד לחיבור RSS תקין. הקוד לא סורק את כל הפוסטים בפייסבוק, יד4 או יד2 ולא עוקף חסימות. כשיש `rss_visual`, ה-workflow מתקין את ספריות הראייה והמחשב מוריד את משקלי המודל; הריצה הראשונה עשויה להיות איטית יותר. ההרצות כפופות למגבלות GitHub Actions וזמינות המקורות.

ניתן לשנות ב-`config.json` את `vision_min_score` (ברירת מחדל 0.08). זהו *ניקוד של מחלקת תמונה*, לא רמת ודאות לזיהוי הגזע; יש לכייל אותו על תמונות אימוץ אמיתיות כדי למנוע החמצות והתראות שווא. תמונות/מודעות אינן מועתקות למאגר אלא נבדקות זמנית; הדשבורד מציג קישור לתמונה המקורית. אין להוריד מאגרי אימון לא מורשים או להציג סיווג כהוכחה לגזע.
